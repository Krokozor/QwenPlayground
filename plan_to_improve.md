# План улучшений QwenPlayground

Рабочий список решений после код-ревью и обсуждения. Цель — повысить надёжность системы, не меняя её характер: агент сохраняет полный доступ внутри доверенной среды, подробные логи и свободу автономной работы.

## Принципы

- Не ограничивать скоуп поиска и доступ агента к workspace.
- Не добавлять подтверждения ради подтверждений: безопасные семантические инструменты важнее запретов.
- Не обрезать данные ради контекста: полный результат сохраняется в артефакт, в разговор идут превью и статистика.
- Не уменьшать логирование: скрываются только фактические значения секретов.
- Состояние агента остаётся на UI-потоке. `Task.Run` допустим только для листовой работы без shared state и не является приоритетной оптимизацией.
- Не вводить без необходимости новые слои идентичности, криптографию и enterprise-роли.

## 1. Идентичность Pigeon и внешние мессенджеры

### Принято

- Внутри доверенной сети токен выполняет две основные роли: отличает владельца от остальных и участников между собой. Auto-join остаётся допустимым.
- Постоянная личность агента — SessionId/GUID. Дополнительный InstanceId не нужен.
- При реальном конфликте скопированных сессий вторая копия может получить новый GUID, переименовать локальную папку и переподключиться как новый участник. Не переименовывать по одному transient duplicate во время быстрого рестарта.
- Внешние мессенджеры — отдельный будущий проект. Их основной сценарий: владелец наблюдает за работой группы и обменивается файлами, а не полноценные агенты внутри Telegram/Discord.
- Bridge получает простую устойчивую идентичность из bot ID или необратимого отпечатка bot token, alias и свободное описание. Формальные Origin/Via/LinkedTo не нужны.
- Файл при отправке в мессенджер загружается как новая копия на сервер мессенджера. Хеш и отслеживание версии после отправки не нужны; достаточно взять файл по пути в момент отправки.

## 15. Runtime-синк почты при изменении настроек (задача от агента, 2026-10-31; по замечанию Kimi; владелец одобрил)

Пробел из раздела 14: set_setting стал писателем почтовых настроек, но не управлял runtime. Возможные состояния: Enabled=true записан, а монитор не запущен; Enabled=false, а опросы идут; ImapHost изменён, а IMAP-соединение осталось со старым сервером (кэш-соединения есть и в MailMonitor._service, и в MailHolder._service).

- [x] `MailRuntime.Decide(previous, current) → None|Start|Stop|Restart` — чистая функция в Core (testable без статиков). Правила: смена connection-полей (хосты/порты/credentials) → Restart; `Enabled && IsConfigured` → монитор работает, иначе нет; PollIntervalSeconds/WakePolicy/WakeSenders/WakeFolders/Email читаются в полёте → None; previous=null → None (базовый снимок). — `src/QwenPlayground.Core/Mail/MailRuntime.cs`
- [x] `MailRuntimeSync` (App): держит последний снимок, `Initialize()` в MainViewModel после авто-старта, `Sync()` — из RefreshSettingsBindings (UI-поток: Stop блокирует до 2с, poll-цикл на UI-контексте). Идемпотентен (TryStart/Stop идемпотентны; двойные вызовы UI-кнопки + синк безопасны). — `src/QwenPlayground.App/Tools/MailRuntimeSync.cs`
- [x] `MailHolder.Reset()` — сброс кэшированного сервиса (DisposeAsync старого).
- [x] Тесты: `MailRuntimeTests.cs` — 13 тестов (Enabled on/off, ImapHost A→B, порт/credentials/refresh-token, PollInterval/wake/Email → None, connection-смена при disabled → Stop, не настроено → настроено → Restart).
- [x] Live-проверка: set_setting Mail.{ImapHost=127.0.0.1, ImapPort=1, Password, Enabled=true} → монитор запустился (state: «mail: inbox 0 unread; poll error: …отверг запрос…»), Enabled=false → монитор остановился (mail-строка исчезла из state); настройки возвращены к исходным.

Критерий: set_setting Mail.Enabled=true/false и смена ImapHost/credentials корректно переключают runtime вживую; «неопасные» поля не рестартуют монитор.
